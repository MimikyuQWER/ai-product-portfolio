# 作品集提交检查清单

## 推荐提交方式

优先提交 Git 仓库链接；如果招聘网站只支持附件，可以提交清理后的 ZIP 压缩包。

## 必须保留

- `src/`、`public/`、`docs/`、`tests/`
- `server.mjs`
- `package.json` 和 `package-lock.json`
- `README.md` 和 `SUBMISSION_CHECKLIST.md`
- `.env.example`、`.gitignore` 和 `LICENSE`
- `vite.config.ts` 与全部 `tsconfig` 文件

## 不要提交

- `node_modules/`：体积大，招聘官执行 `npm install` 会自动安装。
- `dist/`：执行 `npm run demo` 会自动重新构建。
- `.env`：可能包含个人 API 密钥。
- 编辑器缓存、系统文件和运行日志。

## 提交前本地验证

在 `demo` 目录执行：

```bash
npm install
npm run check
npm run demo
```

然后确认：

- <http://127.0.0.1:4173> 可以打开。
- 最新日期为 2026-08-24，标题和摘要没有乱码。
- 任意切换 2–3 个历史日期，正文和图片正常。
- 编辑、撤销、重做和恢复按钮状态合理。
- “本地导出”菜单可以打开。
- 未配置密钥时，“AI 润色”显示中文引导而不是报错。
- 浏览器窄屏下没有横向滚动条。

## 招聘网站项目简介（可直接使用）

> 面向 AI 从业者的信息聚合与日报阅读产品。完整链路覆盖多来源聚合、清洗去重、图片本地化、AI 中文摘要和日报呈现；作品集 Demo 提供 19 份真实快照、401 张本地图片、Markdown 编辑、草稿、撤销、导出及可选 AI 分段润色，无需账号或密钥即可独立运行。

## 建议面试演示顺序

1. 用一句话说明问题：AI 信息很多，但用户缺少稳定的信息压缩入口。
2. 展示日期切换和目录，让面试官看到信息结构。
3. 展示编辑、草稿、撤销和恢复，说明原文只读的安全设计。
4. 展示本地导出，说明内容如何进入用户后续工作流。
5. 展示 AI 配置说明和分章节回退逻辑，强调 AI 不是单点故障。
6. 最后打开 `docs/PRODUCT_DESIGN.md`，讨论产品取舍和下一步指标。
