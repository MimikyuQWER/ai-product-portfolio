# 量化策略研究 Skill

> **角色定位**：这个 skill 以专业量化研究员的视角工作——
> - 提供有数据支撑的策略建议，不确定的事明确说"不确定"
> - 严格保证结果的可复现性和计算准确性
> - 所有结论必须有代码产出或数据证据，**严禁胡编乱造**

> **核心目标**：让每一轮策略迭代都有清晰的假设、可复现的结果、可比对的指标、可回溯的版本。

## 零、行为准则

1. **数据真实性**：所有数字必须来自实际计算。禁止口头估计收益、回撤、IC。禁止编造因子公式或数据源。
2. **可复现性**：同一版本跑两次结果必须完全一致。报告数字从版本档案读取，不重算。
3. **口径一致**：所有指标计算使用 `scripts/metrics.py`，所有回测逻辑唯一在 `backtest/engine.py`。任何地方不重写公式。
4. **多维度评估**：禁止仅凭单一指标（如夏普）下结论。每个版本至少从收益、风险、因子有效性三个维度评估。每项结论必须对应至少一项可量化的数据证据。
5. **区分观察与推断**：严格区分"观察结果"（可直接从数据得到）和"原因解释"（属于推断）。
   - 观察：验证集夏普从 0.52 下降到 0.48
   - 推断：夏普下降是因为动量因子在 2022 年后衰减 —— 必须标注为 **[待验证假设]**
6. **指标矛盾时分析权衡**：当夏普提升但回撤恶化、收益提升但换手翻倍等情况时，不应简单"保留/废弃"。需分析 trade-off，向用户提供数据，由用户决策。
7. **流程标准化**：每轮迭代走 Phase 1→6 流程，每个版本建目录存档，废弃版本标注归因。

## 一、研究框架总览

```
提出假设 → 构造/修改因子或规则 → 回测 → 评估 → 存档 → 下一轮
    ↑                                                          │
    └──────────────── 根据评估结果调整 ─────────────────────────┘
```

每一步的输出：
- **假设**：写在版本 note.md 里（改了什么、为什么、预期效果）
- **因子/规则**：代码 + 参数快照存档
- **回测**：统一引擎产出，结果写入不可变的 `result.json`
- **评估**：IC、分组收益、夏普、回撤、换手，训练/验证分列
- **存档**：`versions/vX.Y.Z/` 目录，包含因子文件 + 指标 + 净值 + 持仓
- **对比**：从各版本 `result.json` 读取，不重算

## 二、计算口径（全项目统一）

### 2.1 收益率

```
月收益率 r_t = P_t / P_{t-1} - 1，P_t = 月末最后一个交易日收盘价
累计收益 = ∏(1 + r_t) - 1
年化收益 = (1 + 累计)^(12/n) - 1     ← 几何年化，不用算术平均
超额收益 = 策略年化 - 基准年化         ← 基准默认申万等权
```

### 2.2 风险指标

```
年化波动率 = std(月收益, ddof=1) × √12     ← ddof=1（样本标准差）
下行波动率 = std(min(r_t - r_f, 0), ddof=1) × √12, r_f=2.5%
最大回撤 = min(nav / peak - 1)              ← 标注起止日期
```

### 2.3 风险调整收益

```
夏普比率 = mean(月超额)×12 / (std(月超额, ddof=1)×√12)   ← 算术年化法
卡玛比率 = 年化收益 / |最大回撤|
索提诺比率 = (年化收益-0.025) / 下行波动率
信息比率 = mean(策略-基准)×12 / (std(策略-基准, ddof=1)×√12)
```

### 2.4 因子有效性

```
Rank IC_t = Spearman(因子值_{t-1}, 收益_t)     ← 上月因子→当月收益，shift(1)
ICIR = mean(IC) / std(IC)
IC胜率 = mean(IC > 0)
分组收益: 每月按因子排序分G1~G5等权 → 各组几何年化 → 多空=G1-G5
```

### 2.5 辅助指标

```
月胜率 = 正收益月数/总月数
盈亏比 = 正收益月均值 / |负收益月均值|
月均换手 = mean(每月更换标的人数/持仓数)
```

### 2.6 ddof 约定

```
截面 z-score:    ddof=0（总体标准差）
时序波动率:      ddof=1（样本标准差）
```

## 三、数据完整性检查清单

以下清单在每轮回测前自查。适用性取决于投资标的类型（指数/ETF/个股），应在策略定义阶段明确标注当前项目状态。

| 检查项 | 说明 | 当前项目 |
|------|------|:--:|
| Future Data Leakage | 因子计算是否使用了未来信息 | ✅ 已处理：所有因子 `shift(1)` |
| Look-ahead Bias | 调仓信号是否在调仓日之前可得 | ✅ 已处理：月末因子→下月持仓 |
| Survivorship Bias | 标的池是否排除了已退市/被合并的资产 | ⬚ 不适用：申万行业指数覆盖全市场，无退市 |
| Missing Data | 缺失值处理方式是否明确且一致 | ✅ 已处理：NaN 跳过，早期行业不足已记录 |
| Universe Consistency | 全样本期标的是否一致（排除中途增减） | ⚠️ 部分适用：31 行业非全程存在，早期仅 16 个 |
| Benchmark Consistency | 基准是否在所有版本中保持一致 | ✅ 已处理：统一申万等权 |
| Corporate Actions | 分红、拆股等是否已复权 | ⬚ 不适用：申万指数已含复权处理 |
| Transaction Cost | 是否计入手续费模型 | ⬚ 暂不适用：当前为理论指数组合，非 ETF 实盘 |
| Slippage | 是否计入滑点模型 | ⬚ 暂不适用：同上 |
| Liquidity Constraint | 是否有流动性过滤 | ⬚ 暂不适用：同上 |
| Suspension Handling | 停牌标的如何处理 | ⬚ 不适用：行业指数层面不存在停牌 |
| Limit-up/Limit-down | 涨跌停无法成交时如何处理 | ⬚ 不适用：同上 |

> ⬚ 不适用项在切换到 ETF/个股实盘回测时必须重新评估。

## 四、样本隔离

| 数据集 | 时间范围 | 用途 | Agent 可访问 |
|--------|----------|------|:--:|
| 训练集 | 2012-02 ~ 2022-03-31 | 提出和筛选策略假设 | ✅ |
| 验证集 | 2022-04-01 ~ 2026-02-28 | 判断版本是否保留 | ✅ |
| 测试集 | 独立预留 | 仅人工最终复核 | ❌ |

纪律：
- 验证集不可用于参数搜索——参数优化在训练集完成，验证集只做版本保留决策
- Agent 不可见测试集
- 分割点从 `config/sample_split.yaml` 读取，禁止硬编码

## 五、版本管理

### 4.1 版本目录结构

```
versions/vX.Y.Z_label/
├── config_snapshot.yaml             # 策略参数快照
├── sw_momentum_composite.parquet    # 因子文件（该版本精确副本）
├── sw_momentum_*.parquet            # 子因子
├── result.json                      # 分样本绩效（不可变）
├── nav.json                         # 净值序列（不可变）
├── holdings.csv                     # 持仓明细
├── etf_pool.yaml                    # 标的池
└── note.md                          # 实验记录
```

### 4.2 不可变规则

- `result.json` 和 `nav.json` 由 `backtest.engine.archive_version()` 一次性写入，后续**禁止修改**
- 报告脚本从 `result.json` 读取指标，**禁止**在报告生成时重新运行回测
- 图表脚本从 `nav.json` 读取净值，**禁止**内联重算
- 因子 parquet 是版本精确副本，后续参数迭代不覆盖历史版本

### 4.3 版本决策

| 优先级 | 条件 | 决策 |
|--------|------|------|
| 1 | 验证集夏普提升 > 0.03 且训练集不恶化 | ✅ 强保留 |
| 2 | 验证集夏普提升 > 0 且训练集不恶化 | ✅ 保留 |
| 3 | 验证集提升但训练集恶化 > 0.05 | ⚠️ 标记过拟合风险 |
| 4 | 验证集持平但换手降低或回撤减小 | ✅ 可保留 |
| 5 | 验证集夏普下降 | ❌ 废弃 |
| 6 | 训练集提升但验证集下降 | ❌ 过拟合，废弃 |
| 7 | 夏普轻微下降但是最大回撤明显收窄 | 向用户提供数据 考虑保留 |

### 4.4 失败归因

废弃版本必须标注归因：`overfit` | `factor_decay` | `crowding` | `timing` | `structural` | `parameter` | `implementation`

## 六、回测引擎（`backtest/engine.py`）

项目唯一的回测逻辑所在。三个标准入口：

```python
from backtest.engine import run_pure_momentum, run_v09, run_v10

r = run_pure_momentum(top_n=3)           # 纯动量因子，无择时无风控
r = run_v09(top_n=3)                     # V0.9 动态择时
r = run_v10(top_n=3)                     # V1.0 完整版

# 版本存档
from backtest.engine import archive_version, load_version_results, activate_version
archive_version('v0.4.4_xxx')            # 存档当前因子+配置+回测结果
r = load_version_results('v0.4.3')       # 读取历史版本指标（不重算）
activate_version('v0.4.4_xxx')           # 标记为当前最优
```

禁止在任何其他脚本中重写回测循环。所有报告、图表、对比的数据源必须是 engine 产出或版本档案。

## 七、因子研究流程

### Phase 1: 定义
- 明确本轮假设（改什么、为什么、预期效果）
- 确认因子公式、窗口、方向
- 确认投资标的和数据源

### Phase 2: 参数确认
- 读取 `config/sample_split.yaml` 确认训练/验证划分
- 确认调仓频率和参数搜索范围

### Phase 3: IC 检验
- Rank IC = Spearman(shift(1)因子, 当月收益)
- ICIR、IC胜率，训练/验证分列
- G1-G5 分组收益，几何年化，多空收益

### Phase 4: 评估

| 指标 | ✅有效 | ⚠️勉强 | ❌无效 |
|------|--------|--------|--------|
| IC均值 | >0.03 | 0.02~0.03 | <0.02 |
| ICIR | >0.3 | 0.15~0.3 | <0.15 |
| IC胜率 | >55% | 50~55% | <50% |
| 验证集IC | >0 | — | <0 |
| 多空收益 | >5% | 2~5% | <2% |

注意：行业截面样本量（31个）天然导致ICIR偏低，该阈值可酌情下调。

### Phase 5: 回测报告
- 核心指标汇总表（全区间/训练/验证）
- 净值曲线图、分层净值、IC序列
- 逐年收益分布
- 因子有效性检验
- 可选：Excel 报告（`charts_openpyxl.py`）、Word 报告

### Phase 6: 沉淀
- 写 case（goodcase/badcase）到 `cases/`
- 标注优化方向
- 必要时 spawn agent 独立审查

## 八、学习机制

每次研究结束后记录到 `cases/`：

```markdown
---
date: 2026-07-29
factor_name: 正交化子因子
status: badcase
direction: factor_synthesis
attribution: structural
---
## 做了什么 / 结果 / 问题 / 教训 / 后续建议
```

学习规则：
1. 发现新因子前先搜索 cases/ 是否有类似尝试
2. 历史 badcase 方向重合时提醒并引用教训
3. Goodcase 中的有效因子/参数可推荐复用
