# Demo PRD 验收矩阵

更新时间：2026-08-27

这份矩阵把初版 PRD 的要求拆成“界面是否可见、后端是否实现、是否有验证、当前边界”四项。它用于区分已经闭合的 Demo 主链路和暂不纳入本轮的生产能力。

## 一、主链路验收

| PRD 要求 | 当前结论 | 验证方式 / 交付位置 | 当前边界 |
|---|---|---|---|
| 研究配置先于计算 | 已实现 | PC 与财富端均先保存资产、基准、起止日期、训练/验证切分、滞后和成本；后端校验日期顺序 | 资产类型目前是 Demo 数据入口；实际样本仍是合成指数池 |
| 两种产品形态独立完成主流程 | 已实现 | `research.html` 与 `wealth.html` 均可独立完成七步流程并调用同一运行、决策和历史接口 | 两者共享后端与合成数据，不共享页面状态 |
| 自然语言研究想法转成研究方案 | 已实现（本地规则版） | `assistant.js` 识别资产、因子、观察窗口、频率、持仓数量和择时条件，并生成结构化提案 | 不调用外部大模型；保证离线、可复现，后续可替换为受控模型服务 |
| 单因子研究 | 已实现 | 动量、低波、价值 / 市净率；公式、经济意义、IC、ICIR、分组收益、敏感性和换手结果来自 `demo_pipeline.py` | 任意新公式暂不支持在线生成，当前以示例因子为范围 |
| 因子正交化与综合 | 已实现 | 同一截面残差化；三项权重可在两个界面中配置，后端标准化后重算 | 还不是完整的组合优化器 |
| 因子采纳 / 调整 / 废弃 | 已实现 | 两个界面均要求填写原因；调整生成版本；决策写入 `/api/research/decision` | 尚未接入多人数据库和权限审批 |
| 风控与调仓 | 已实现 | 统一回测入口处理信号滞后、只做多、总敞口、调仓和交易成本 | 风控规则仍是 Demo 级约束，不覆盖生产交易系统 |
| 多因子策略 | 已实现 | `composite` 策略；因子版本、权重和 Top N 可见并可配置 | 当前仍是 Top N 等权，不含正式组合优化 |
| 动量择时策略 | 已实现 | 12 个月基准趋势过滤；趋势转弱仓位可配置，下一期执行 | 仅用于演示趋势过滤，不构成正式投资口径 |
| 策略设计与回测 | 已实现 | 策略契约、净值、年化收益、夏普、索提诺、最大回撤和持仓轨迹 | 报告为简版，不覆盖完整归因报告 |
| 规则校验 / Golden Test | 已实现 | 前视偏差、净收益、净值、配置和数据指纹等检查；`tests/` 有回归测试 | Golden 集合规模仍小，后续可增加更多边界样本 |
| 运行档案 | 已实现 | 点击“运行并归档”调用 `/api/research/run`，生成七阶段 `input.json` / `output.json`、`run-manifest.json` 和 `run-output.json` | 当前档案写本地文件，不提供多人并发和权限管理 |
| 版本与历史 | 已实现 | 运行号唯一、不覆盖旧运行；`/api/research/history` 和单次运行读取接口供两个界面复核 | 本地文件仍不是多人数据库；离线动作只标记为未归档 |
| 专业协作 / 自主研究模式 | 已实现（Demo 级） | 两端可切换模式；专业模式逐步人工确认，自主模式由 AI 组织建议但保留研究方案与因子审批 | 当前不接在线大模型，执行逻辑仍由确定性规则约束 |
| 独立研究验证 | 已实现 | 后端独立校验器仅接收配置与运行结果，检查滞后、样本切分、成本、正交化、Golden Test 和数据指纹 | 属于最小规则集，不等同于生产级模型风险管理 |
| 首次使用指引 | 已实现 | PC 与手机端每次刷新自动展示；标题区可再次打开 | 演示版本按刷新触发，未接账户级已读状态 |

## 二、PRD 中已经明确、但本 Demo 有意不做的能力

| 能力 | 结论 | 原因 |
|---|---|---|
| 外部大模型直接执行研究 | 不纳入本轮 | Demo 先验证流程和边界，避免把概率输出冒充金融计算结果 |
| 任意自然语言生成新因子代码 | 不纳入本轮 | 需要代码沙箱、字段权限、公式校验和回归数据集，超出轻量 Demo 范围 |
| 股票、基金、债券的真实数据适配 | 部分实现 | 页面和配置支持资产类型入口，但本轮真实样本只有 iFinD 指数收盘价；没有用代理数据冒充基本面数据 |
| AI 研究记忆 | 部分实现 | 当前通过运行档案和本地决策文件保留上下文；还没有独立的研究记忆检索层 |
| 多人协作、权限、正式审批 | 不纳入本轮 | 需要服务端账户、权限、数据库和审计系统 |

## 三、实际验证结果

- Demo、归档、Runner、独立校验与启动入口定向测试：22 项通过。
- JavaScript 语法检查：`app.js`、`research.js`、`assistant.js`、`wealth.js` 均通过。
- 本地服务健康检查：`GET /api/health` 返回 200。
- 真实运行接口：`POST /api/research/run` 已成功返回综合因子、动量择时和等权基准结果。
- 财富端浏览器联调：自然语言提案、配置、因子测试、三因子审批、正交化、双策略回测、策略审批和历史页完成 7/7。
- PC 端浏览器联调：配置、因子测试、因子 v1.1 调整、40/35/25 权重、双策略与双曲线报告、审批和历史页完成 7/7。
- 运行归档：单次运行生成 7 个阶段目录，每个目录都有 `input.json` 和 `output.json`。
- 决策归档：`POST /api/research/decision` 已成功生成独立决策文件。
- iFinD 冒烟：5 个指数、2024-02-29 至 2025-12-31，已跑通动量、低波、动量择时和等权基准。
- 全量测试还存在 1 个历史基线失败：`tests/test_baseline_20260824.py` 报告 `data/raw/domestic_index_daily.parquet` 的文件指纹与旧基线不一致。该文件不是本轮 Demo 改动，当前没有用破坏性操作覆盖它；应单独确认是数据更新还是基线需要重建。

## 四、方法论依据

本轮验收参考本地知识库中的：

- `patterns/量化策略开发前置检查.md`：先验证数据通路，再做小样本闭环；明确数据限制、参数敏感性和策略弱点。
- `patterns/策略自进化迭代框架.md`：策略协议、版本管理、训练 / 验证 / 测试集权限隔离，一个版本只改一个主要假设。
- `entities/AI开发协作框架.md`：Demo 先演出主链路，MVP 要求核心输入到输出真实可跑；确定性步骤交给脚本，AI 负责理解和建议。
- `entities/AI评测和调优体系.md`：结构化输出、规则校验、回归防护优先于单纯 Prompt 约束。
