# 结构化个人知识库系统 · 设计思路详解

> 本文件是对 `README.md` 的展开说明，重点回答三个问题：
> **为什么要这么设计？每条数据流怎么走（输入→处理→输出）？AI 怎么用它？**
> 系统定位：一套"AI 可检索、可维护、可溯源"的个人知识管理系统，覆盖量化金融 + AI 产品双领域，当前沉淀约 **159 页 Markdown**。

---

## 一、为什么需要"结构化"知识库（设计动机）

普通笔记/网盘的问题是：信息进得去、出不来——AI 读了一堆 Markdown，却分不清哪条是"事实"、哪条是"我个人观点"、哪条"可能已经过时"。

本系统的核心设计目标是让 AI 在**不污染人类笔记**的前提下，高效、可溯源地消费个人知识。三个硬约束贯穿始终：

1. **原始素材只读**（`raw/` 目录 AI 不可改），保证溯源链不断。
2. **每条事实必须可溯源**到 `raw/` 原文，不确定就标"待补充"，绝不用常识填空。
3. **默认更新旧页面、不建新页面**，避免知识碎片化。

## 二、整体架构（数据流入 → 结构化 → AI 检索）

```
┌─────────────── 数据流入（三通道） ───────────────┐
│  飞书知识库      研报 PDF/PPTX       Claude 会话      │
│  (OAuth同步)     (双工具解析)        (自动Digest)     │
└───────────────┬──────────────┬──────────────────┘
                │              │
                ▼              ▼
          raw/feishu/    raw/上农商资管材料/   inbox/
          (markdown)     (markdown)          (摘要)
                └──────────────┬───────────────┘
                               ▼
                  统一 YAML frontmatter 标注
                  type / domain / created / updated
                               ▼
        ┌──────────────┬──────────────┬──────────────┐
        │  entities/    │  judgments/  │  patterns/   │  observations/
        │  知识实体      │  个人判断     │  工作方法     │  时间性观察
        └──────┬───────┴──────┬───────┴──────┬───────┘──────┬───────┘
               └──────────────┴──────────────┴──────────────┘
                              ▼
                    index.md（领域索引）
                              ▼
                  AI 渐进式披露检索（L1→L2）
```

## 三、三条数据流入通道（输入/处理/输出）

### 通道 1：飞书知识库同步（`sync_feishu.py`）

| 环节 | 说明 |
|------|------|
| **输入** | 飞书开放 API 下的 3 个知识空间：AI 知识库（16 篇）、金融专业知识（13 篇）、秋招暑期准备（4 篇） |
| **处理** | OAuth 用户授权 → 递归遍历节点树 → 对每篇文档算 **SHA-256 内容指纹** → 与本地比对 → **仅写入有变更的内容** → 记录 changelog |
| **输出** | `raw/feishu/` 下的 Markdown 文件 + 变更日志 |
| **关键设计** | ① 增量同步（不重复拉取，省 token）；② 指纹去重避免"假更新"；③ 支持 headless 模式（Windows 定时任务每日 9:00 跑），token 过期自动刷新 |

**为什么这么设计**：知识库会持续更新，全量同步既慢又浪费。SHA-256 指纹让"只有真变了才动"成为自动行为，AI 每次摄入都基于干净增量。

### 通道 2：研报入库（PDF/PPTX → Markdown）

| 环节 | 说明 |
|------|------|
| **输入** | 券商研报 PDF / PPTX 原文件 |
| **处理** | **双工具对比择优**：MarkItDown（微软开源，AI 增强语义提取）+ pdfplumber（基于规则的精确文本定位 + 表格检测）；再用 4 个维度自动评分——颜色值残留、空表格碎片、数字碎片、文本密度 |
| **输出** | 质量检查通过后存入 `raw/上农商资管材料/`（含 `### 📊 表格X.Y` 标记与图片占位符+原始路径） |
| **关键设计** | 不是"哪个能用就用哪个"，而是两个工具各跑一遍、按质量分高者保留，显著降低解析错误 |

### 通道 3：会话自动 Digest

| 环节 | 说明 |
|------|------|
| **输入** | 每次 Claude Code 对话结束后的会话内容 |
| **处理** | 自动生成结构化摘要 |
| **输出** | `inbox/` 下的摘要文件（含 `session_id`、`topics`、关键产出），供后续"整理"时归档 |

## 四、结构化方法：4 种页面类型

所有页面**统一 YAML frontmatter**（`type` / `domain` / `created` / `updated`），让 AI 第一眼就能分类。

| 类型 | 用途 | 示例 | 特殊字段 |
|------|------|------|---------|
| **Entity（实体）** | 知识实体：框架、策略、因子、数据源 | 资产配置投研框架、动量因子 | `category`、`status` |
| **Judgment（判断）** | 个人观点与判断 | "宏观打分因子对行业轮动边际贡献有限" | `confidence`（0–1）+ 支撑证据 + 反面论证 |
| **Pattern（方法）** | 可复用工作方法 | 量化策略开发前置检查清单 | `times_used` 计数器（用一次 +1） |
| **Observation（观察）** | 有时间性的观察 | 市场周度观察 2026W26 | `date`、`data_freshness` |

**设计要点**：把"客观知识"和"主观判断"用类型硬分开。AI 引用判断时，**必须同时看到支撑证据与反面论证**，避免把个人观点当成事实输出。

## 五、渐进式披露：单文件内分层

每个页面内部按三层组织，AI 按需深入、**够用即停**，省 token 也省时间：

```
L1 frontmatter   → AI 始终可见（类型 / 领域 / 时效性）
L1 大纲索引       → AI 50 行内掌握全貌
L1 详细内容       → 完整知识（人类详读 + AI 需要时深入）
L2 深层导航       → 指向 raw/ 原始材料 + [[关联页面]]
```

检索逻辑：**先读大纲索引 → 信息够了就停 → 不够往下翻 → 还不够追 raw/ 原文**。这正是"结构化"相对"一堆 Markdown"的核心价值。

## 六、AI 检索与协作机制

### 1. 交叉引用网络（`[[页面名]]`）
- 每个页面**至少有 1 个入站链接**（无孤立页面）
- Judgment **必须**链接到支撑证据来源
- 跨领域连接用 `domain` 字段区分，不建重复页面

### 2. 时效性控制
每个含数据的页面标注 `data_as_of`（数据截止日）和 `data_freshness`（刷新频率：实时/日度/周度/月度/季度/年度/框架/快照）。AI 读取时自动检查——**超过 1 个月的市场数据标注"可能已过时"**，防止拿着过期数据下结论。

### 3. 数据优先级（AI 取数顺序）

| 优先级 | 来源 | 场景 |
|--------|------|------|
| P0 | iFinD / 同花顺实时 API | 行情、估值、最新财务 |
| P1 | Wiki 结构化页面 | 框架性知识、审核后的数据 |
| P2 | `raw/` 原始材料 | 研报静态快照（使用时标注时间） |

### 4. 四类 AI 协作流程
- **摄入**（"摄入这个"）：读素材 → 总结 3 个要点确认 → 更新/创建页面 → 更新 `index.md`
- **沉淀**（"沉淀 wiki"）：回顾对话 → 提取判断/事实/方法 → 写入对应页面 → 检查矛盾
- **健康检查**（"整理一下"）：清 `inbox` 积压 → 查孤立页面 → 查矛盾判断 → 查过期数据
- **答疑**（自动触发）：检测疑问句 → 查 wiki + iFinD → 给出**可溯源**答案

## 七、核心原则（工程纪律）

1. **默认更新旧页面**，不建新页面。宁可一个厚页面，也不要很多薄页面。
2. **每条事实性陈述必须可溯源**到 `raw/` 原文。不确定标注"待补充"，不用常识填空。
3. **`raw/` 目录只读**，AI 不能修改原始素材。
4. **每次实质性更新后 `git commit`**，格式：`{操作}: {简述}`。
5. **跨领域连接是好事**——知识网络的价值在连接处。

---

## 八、对 AI 产品岗的亮点

- **把"AI 如何消费知识"当成产品设计问题**：frontmatter 类型系统、渐进式披露、时效性控制，本质是一套"人机协同的知识接口协议"。
- **可溯源优先于聪明**：宁可标"待补充"也不编造，与地址审核 Agent 的"反幻觉"理念一脉相承。
- **增量与去重工程化**：SHA-256 指纹同步、双工具对比择优，体现工程落地能力，而非只谈概念。
