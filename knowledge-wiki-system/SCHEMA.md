# 个人知识库 Schema

> 角色：AI产品经理 / 二级市场投资者（权益、固收、资产配置）
> 领域：量化投资、权益市场、固收市场、资产配置、AI金融、AI产品

## 这是什么

一个由 AI Agent 维护的个人知识库，覆盖多个领域。
- 我负责：策展素材、做判断、问好问题、定期复盘
- AI 负责：摘要、归档、交叉引用、一致性维护、健康检查

---

## 目录结构

```
├── SCHEMA.md      ← 本文件
├── index.md       ← 全局索引（按领域分区）
├── entities/      ← 知识实体（框架、策略、因子等，单文件内含大纲索引+详细内容）
├── patterns/      ← 可复用的工作方法
├── observations/  ← 周报、月报等有时间性的观察
├── judgments/     ← 个人判断和观点（带置信度）
├── raw/           ← 原始素材（只读归档，信息不够时来查）
├── tools/          ← 可复用脚本资产（raw提取/合并/同步）
│   └── README.md  ←    工具目录（AI不需要每次重写脚本）
└── inbox/         ← 快速记录入口（auto digest 也写入这里）
```

## 页面类型（所有领域通用）

### Entities（实体）

描述具体的事物。所有 Entity 必须标注 `domain`。

页面格式：
```markdown
---
type: entity
domain: 量化金融 | AI产品 | 通用
category: （见各领域分类表）
created: {日期}
updated: {日期}
---

# {实体名}

一句话定义。

## 关键事实
- 事实1
- 事实2

## 与其他实体的关系
- 相关：[[xxx]]
```

### Judgments（判断）

我自己的观点和论断。**这是最有价值的页面类型。**

页面格式：
```markdown
---
type: judgment
domain: 量化金融 | AI产品 | 通用
created: {日期}
updated: {日期}
confidence: 0.0-1.0
---

# {判断的一句话表述}

## 判断
2-3 句话，直接、有锐度。

## 支撑证据
1. 证据1（强度：强/中/弱）
2. 证据2

## 反面论证
- 反面观点

## 判断历史
- {日期}：初始形成，置信度 X
```

置信度指南：
- 0.9+：多源交叉验证
- 0.7-0.9：有数据支撑但样本有限
- 0.5-0.7：初步判断，需更多验证
- <0.5：直觉/假设

### Patterns（方法）

反复使用的工作方法和流程。某个做法出现 3 次以上就值得提炼。

页面格式：
```markdown
---
type: pattern
domain: 量化金融 | AI产品 | 通用
created: {日期}
updated: {日期}
times_used: 0
---

# {方法名}

## 适用场景
什么时候用这个方法。

## 步骤
1. ...
2. ...

## 关键注意点
- ...
```

### Inbox（收件箱）

快速记录，格式自由，带日期。定期整理——归档到正式页面或判断不值得保留则删除。

## 操作流程

### 摄入（Ingest）

用户说"摄入这个：{内容}"时：
1. 读完素材
2. 向用户总结 2-3 个关键要点，确认方向
3. 更新或创建相关的 entity/judgment/pattern 页面
4. 更新 index.md
5. 如果新信息和已有判断矛盾——标注矛盾，问用户怎么看

### 沉淀（Crystallize）

用户说"沉淀 wiki"时：
1. 回顾本次对话，提取关键产出（新判断、新事实、新方法、判断变化）
2. 将产出写入 wiki 对应页面（新建或更新）
3. 更新 index.md
4. 检查是否与已有页面矛盾
5. 跨领域连接：检查新内容是否与另一个领域的页面有关联

### 快速记录

用户说"记一下：{内容}"时：
1. 写入 inbox/，带日期
2. 如果明确涉及已有页面——直接更新那个页面

### 健康检查（Lint）

用户说"整理一下"或"整理 inbox"时：
1. inbox/ 有没有未处理的内容——归档到正确位置
2. 有没有孤立页面（没被任何其他页面引用）
3. 有没有矛盾的判断（包括跨领域矛盾）
4. 有没有重要概念被多次提到但没有自己的页面
5. 有没有长期未更新的判断需要复审

---

## 核心原则

- 默认更新旧页面，不建新页面（除非是全新实体/判断/方法）
- 宁可一个厚页面，也不要很多薄页面——每个文件前三分之一是提纲式大纲索引（方便AI快速定位），后三分之二是完整详细内容
- 每个页面至少有 1 个其他页面链接到它（用 [[页面名]] 格式）
- 判断页必须有至少 1 条支撑证据
- 不确定的信息标注置信度，不要假装确定
- raw/ 目录里的文件是只读的原始素材，AI 不能修改
- 跨领域连接用 `domain:` 区分，不建重复页面——同一个实体如果跨两个领域，用 `domain: 量化金融, AI产品`

---

## 交叉引用

- 用 `[[页面名]]` 格式做内部链接
- 每个页面至少 1 个入站链接
- 判断页必须链接到支撑证据来源
- 跨领域链接是好事——知识网络的价值在连接处

---

## 版本管理

- 每次有实质性更新后 git commit
- commit 格式：`{操作}: {简述}`（如 `ingest: 摄入XX研报`、`update: 更新动量因子判断`）

## 渐进式披露（单文件内分层）

AI 和人共读同一个文件作为第一层。文件前面是提纲式索引 + 知识骨架（AI 快速定位），后面是详细内容。信息不够时再去 raw/。

```
单文件结构：

├── L1 frontmatter   → AI 始终可见
├── L1 大纲索引       → AI 读完索引就理解全貌（30-50行）
├── L1 详细内容       → 完整知识（人类详读 + AI 需要时深入）
└── L2 深层导航       → 指向 raw/ 原始材料 + 关联页面
```

### 页面标准格式

```markdown
---
(L1 frontmatter)
---

# 标题

> 🎯 TL;DR：一句话

## 大纲索引
（用列表树把全文结构亮出来，AI 50行内掌握骨架：
- 第一章：xxx
  - 核心指标
  - 关键结论
- 第二章：xxx
- 关联页面）
```

## 详细内容
（完整方法论、指标详解、案例、数据表格）

## 🔗 深层导航
- raw/ 原始材料
- 关联页面 [[xxx]]
```

检索逻辑：AI 先读大纲索引 → 信息够了就停 → 不够则往下翻详细内容 → 还不够追 raw/。

### 时效性标记

每个包含数据的页面必须在 frontmatter 中标注：

- `data_as_of`：数据截止日期（必填）
- `data_freshness`：刷新频率（实时/日度/周度/月度/季度/年度/框架/快照）

AI 读取时检查：超过 1 个月的市场数据 → 标注"可能已过时，建议查同花顺最新值"。

### 数据优先级

| 优先级 | 来源 | 说明 |
|--------|------|------|
| P0 | 同花顺实时数据接口 | 行情、估值、财务数据第一来源 |
| P1 | Wiki 页面结构化数据 | 经审核的框架性数据 |
| P2 | raw/ 原始材料静态数据 | 特定时间点快照，使用时须标注时间 |

### 内容原则（补充）

- 页面中严禁编造内容——所有陈述须可追溯到 raw/ 原文（比上文"不要假装确定"更进一步：不仅不确定要标注，确定的也必须来自原始材料）
- 删除与主题无关的内容（免责声明、版权信息、广告等）
