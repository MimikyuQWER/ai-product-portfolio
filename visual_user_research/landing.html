传统玩家访谈的三个瓶颈

原神海外用户研究团队需要提前了解不同区域玩家对新内容的反馈。但真人访谈在效率、规模和一致性上存在系统性问题。

瓶颈一

招募排期 2–4 周

跨国招募特定画像的目标玩家周期漫长，遇到小众群体时更长。产品迭代节奏等不起。

瓶颈二

单轮仅覆盖 3–5 人

样本量太小，结论碎片化。想达到有统计意义的样本量需要投入数倍的人力和预算。

瓶颈三

研究员理解偏差

不同人对同一句玩家反馈的解读可能完全不同——「对内容不满」还是「对节奏不满」？主观偏差难以消除。

三级回答生成体系

不同于通用 Chatbot——每条回答先判断证据充分性，再选择对应的生成策略。回答可追溯、可验证、可评估。

01

原文可答

检索召回访谈原文 → AI 做自然转述和口吻润色 → 引用出处。不走角色扮演，忠实还原玩家本意。

02

证据可推演

检索原文 / BI 字段 / 画像证据 → 确定可用论据 → 调用角色扮演生成回答。只引用本轮召回的证据，不越界推断。

03

证据不足

不调用角色扮演 · 不强行推断 · 直接告知资料不足。诚实的「不确定」比胡编的回答更值得信赖。

核心功能

将用户研究员「筛选 → 访谈 → 对比 → 提炼」的完整工作流，转化为可交互的 AI 工具。

产品设计理念

从产品迭代文档中沉淀的核心原则，指导了 v2 到 v7 的每次决策。

信任源于透明，而非黑盒

每条回答展示完整推理链路。使用者不是在「信 AI」，而是在验证 AI 的判断——用到了哪些依据、做了哪些推断、存在什么风险。

三级评分体系：结论 50 + 原因 40 + 风格 10

回答结论一致、推理原因一致、语言篇幅合适。每次 Skill 迭代后全量重跑测试集，确保不退化。

Agent 驱动调优闭环

Benchmark 评测 → 差异归因 → 生成优化方案 → 人工审核 → 应用修改 → 回归测试。迭代过程可量化、可回溯。

硬标签筛选，软标签理解

人口学标签用于精确筛选；3–5 个业务意义软标签（社交驱动型/竞技硬核/碎片逃离型）用于真正理解用户。

禁止「机器预习」

不能用测试集训练 AI——又做选手又做裁判。优化方向来自其他问题的反馈，测试集仅用于验证进步。

建立信任 = 面试逻辑

简历（数据档案）+ 沟通风格（语言润色）+ 内容（言之有物）+ 活人感（不 OOC）——让业务方愿意用、敢于信。
